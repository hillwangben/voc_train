# 语音垂直训练资产包训练平台集成使用说明

## 1. 适用范围

本文档用于将 `speech_train_preset` 集成到已有 AI 训练平台。资产包采用统一容器方案，一个算法资产承载 10 类语音训练流程：

1. 语音识别：`asr`
2. 复杂噪声语音增强：`noise_enhancement`
3. 跨信道连续语音识别：`cross_channel_asr`
4. 小语种连续语音识别：`low_resource_asr`
5. 混合语种连续语音识别：`code_switch_asr`
6. 声纹识别：`speaker_verification`
7. 语音智能交互：`speech_interaction`
8. 多语言语音翻译：`speech_translation`
9. 语音转写：`transcription`
10. 语音纠错：`speech_correction`

## 3. 平台导入步骤

### 3.1 导入环境资产

环境资产目录：

```text
env/speech_train_all-env/
```

平台读取：

```text
env/speech_train_all-env/INFO.ini
```

关键字段：

```ini
[base]
name = speech_train_all-env
version = v1
image_id = cetc-harbor.registry.com:30003/exp/ubuntu22.04-python3.10-cuda12.1-torch2.1:speech-train-all-v1
```

正式平台部署时需要完成：

```bash
docker build -t cetc-harbor.registry.com:30003/exp/ubuntu22.04-python3.10-cuda12.1-torch2.1:speech-train-all-v1 env/speech_train_all-env
docker push cetc-harbor.registry.com:30003/exp/ubuntu22.04-python3.10-cuda12.1-torch2.1:speech-train-all-v1
```

如果平台采用离线镜像导入，可执行：

```bash
docker save cetc-harbor.registry.com:30003/exp/ubuntu22.04-python3.10-cuda12.1-torch2.1:speech-train-all-v1 | gzip > env/speech_train_all-env/speech_train_all-env.tar.gz
```

当前交付包默认 CPU-only，`config.yaml` 中 `gpu: 0`。镜像名称保留了 `cuda/torch` 字段是为了兼容已有命名规范；平台可按实际情况改为无 CUDA 基础镜像。

## 4. 容器运行约定

平台运行容器时建议挂载：

| 容器路径 | 来源 | 说明 |
| --- | --- | --- |
| `/workspace/algorithm` | 算法工程 `alg/speech_train_all-alg/main` | 执行脚本和源码 |
| `/workspace/input` | 数据集解压目录 | 音频和标注 |
| `/workspace/model` | 模型解压目录 | 基础模型或真实 CPU 小模型 |
| `/workspace/output/train` | 平台输出目录 | 训练结果 |
| `/workspace/output/evaluate` | 平台输出目录 | 评估结果 |
| `/workspace/output/adapt` | 平台输出目录 | 模型适配结果 |

建议环境变量：

```bash
TASK_TYPE=asr
BACKEND=cpu_reference
DATA_DIR=/workspace/input
MODEL_DIR=/workspace/model
SAVE_DIR=/workspace/output/train
PYTHON_BIN=python3
```

## 5. 任务参数说明

平台通过 `TASK_TYPE` 或 `config.yaml` 中的 `parameters.task_type` 选择流程。

| task_type | 说明 | 推荐 backend |
| --- | --- | --- |
| asr | 语音识别 | `vosk_small_en_us_0_15`、`cpu_reference` |
| noise_enhancement | 复杂噪声语音增强 | `stdlib_audioop_cpu_denoise`、`cpu_reference` |
| cross_channel_asr | 跨信道连续语音识别 | `vosk_small_en_us_0_15`、`cpu_reference` |
| low_resource_asr | 小语种连续语音识别 | `vosk_small_en_us_0_15`、`cpu_reference` |
| code_switch_asr | 混合语种连续语音识别 | `vosk_small_en_us_0_15`、`cpu_reference` |
| speaker_verification | 声纹识别 | `stdlib_audio_energy_embedding`、`cpu_reference` |
| speech_interaction | 语音智能交互 | `vosk_small_en_us_0_15_plus_rule_intent_model`、`cpu_reference` |
| speech_translation | 多语言语音翻译 | `small_dictionary_translation_model`、`cpu_reference` |
| transcription | 语音转写 | `vosk_small_en_us_0_15`、`cpu_reference` |
| speech_correction | 语音纠错 | `small_lexicon_correction_model`、`cpu_reference` |

`cpu_reference` 是内置轻量验证后端，不依赖外部模型下载，适合平台导入、任务调度和结果产物验收。真实模型测试脚本使用 Vosk small 模型和标准库 CPU 小模型后端。

## 8. 数据标注格式

数据集标注使用 JSON Lines，每行一个样本。

通用字段：

```json
{
  "utt_id": "asr_zh_0001",
  "task_type": "asr",
  "audio": "audio/train/asr_zh_0001.wav",
  "text": "打开设备开始识别",
  "language": "zh",
  "speaker_id": "spk001",
  "channel": "mic_1"
}
```

任务专属字段：

| 任务 | 字段 |
| --- | --- |
| 语音增强 | `clean_audio`、`noise_type` |
| 跨信道 ASR | `channel` |
| 小语种 ASR | `language` |
| 混合语种 ASR | `language=zh-en` 或多语种标识 |
| 声纹识别 | `speaker_id`、`enroll_speaker_id`、`test_speaker_id`、`same_speaker` |
| 语音交互 | `intent`、`slots` |
| 语音翻译 | `target_language`、`target_text` |
| 语音纠错 | `noisy_text`、`corrected_text` |

平台上传自有数据集时，应保证：

- `task_type` 与平台任务配置一致。
- 音频路径为数据集根目录下的相对路径。
- 单个数据集可包含多个任务，但训练时按 `task_type` 过滤。
- 每个任务数据量可独立控制，验收测试建议小于 50 条。

## 11. 平台集成验收建议

平台侧建议按以下顺序验收：

1. 资产导入验收：识别 `alg`、`env`、`dataset`、`model` 四类资产。
2. 镜像验收：镜像可启动，`python3` 可用，脚本具备执行权限。
3. 数据验收：数据集 zip 可解压，JSONL 可解析，音频路径存在。
4. 单任务验收：选择 `asr` 跑一次 `train` 和 `evaluate`。
5. 多任务验收：依次修改 `TASK_TYPE` 跑 10 类流程。
6. 结果验收：平台能采集 `checkpoint.json`、`train_metrics.json`、`metrics.json`。
7. 资源验收：确认训练任务不申请 GPU，CPU/内存配置符合平台配额。

## 12. 常见问题

### 12.1 平台没有 `python` 命令

脚本默认使用：

```bash
PYTHON_BIN=python3
```

如平台 Python 路径不同，可覆盖：

```bash
PYTHON_BIN=/opt/conda/bin/python
```

### 12.2 真实 Vosk 模型目录不存在

确认模型目录：

```text
model/real_cpu_models/vosk-model-small-en-us-0.15
```

如果平台不需要真实模型测试，只跑 `cpu_reference` 流程即可。

### 12.3 数据集中包含多个任务

算法会按 `task_type` 自动过滤样本。平台运行某个任务时，应确保配置中的 `TASK_TYPE` 与数据样本字段一致。

### 12.4 指标看起来是代理指标

当前交付包包含两类指标：

- 真实 ASR 指标：Vosk 推理输出的 WER/CER。
- CPU 小型后端代理指标：用于训练平台流程验收，如 `snr_improvement`、`bleu_proxy`、`correction_f1`。

生产环境可将后端替换为 `docs/open_source_cpu_models.json` 中列出的完整开源模型。

## 13. 10 类任务算法模型与测试逻辑说明

本章节按“模型说明”角度描述每个任务的算法定位、推荐开源 CPU 小模型、当前交付包中的离线测试后端、测试逻辑和指标输出。当前平台验收默认使用 `cpu_reference` 后端，保证 10 类流程无需联网、无需 GPU 即可完成训练和评估。真实开源模型可按 `docs/open_source_cpu_models.json` 中的后端清单逐步替换。

### 13.0 当前系统实际训练模型

当前系统 10 个 CPU 训练流程实际使用的模型后端为 `cpu_reference`，设备策略为 `cpu_only`。该后端是交付包内置的任务级参考训练模型，用于在已有训练平台中验证数据接入、训练调度、评估调度、指标回传和产物归档能力；它不依赖 GPU，也不依赖联网下载外部权重。

实际训练模型和配置位置如下：

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 模型元数据 | `model/speech_train_base-model/config/model_info.json` | 声明 `default_backend=cpu_reference`、`device_policy=cpu_only`、训练参数和 10 类任务指标。 |
| 参考模型描述 | `model/speech_train_base-model/model/cpu_reference_model.json` | 当前 10 类流程实际使用的 CPU 参考模型描述文件。 |
| 模型占位文件 | `model/speech_train_base-model/model/model.pt` | 兼容训练平台模型文件扫描和模型包归档的占位文件。 |
| 真实 CPU ASR 资源 | `model/real_cpu_models/vosk-model-small-en-us-0.15` | 已随包保留的 Vosk small English 开源模型，可用于 ASR 类任务真实 CPU 推理替换。 |

### 13.1 语音识别 ASR：`asr`

**模型定位**：将输入语音转换为文本，面向普通语音识别和领域语音识别训练。

**推荐开源 CPU 模型**：

- Vosk small：离线 CPU ASR，小模型，适合嵌入式和训练平台 CPU 验证。
- sherpa-onnx int8：ONNX/int8 流式 ASR，适合 CPU-only 推理。
- Whisper tiny：多语言 ASR，小参数量，CPU 可运行但速度较慢。

**当前离线测试后端**：`cpu_reference`。该后端读取 `task_type=asr` 的 50 条样本，基于标注中的 `text/prediction` 字段完成 ASR 训练和评估流程验证。

**训练逻辑**：

1. 读取 `labels/train.jsonl` 中 `task_type=asr` 的样本。
2. 校验音频路径、文本、语种、说话人和通道字段。
3. 统计样本数、通道数、语种分布。
4. 写出 `checkpoint.json` 和 `train_metrics.json`。

**评估逻辑**：

1. 按通道聚合样本。
2. 将 `text` 作为参考文本，将 `prediction` 作为识别输出。
3. 计算整体 WER/CER 和每个通道的 WER/CER。

**输出指标**：`wer`、`cer`、`channel_metrics`。

### 13.2 复杂噪声语音增强：`noise_enhancement`

**模型定位**：对带噪语音进行增强，提升语音清晰度和后续识别鲁棒性。

**推荐开源 CPU 模型**：

- RNNoise：轻量 RNN 降噪模型，适合 CPU。
- DeepFilterNet：语音增强模型，CPU 可运行，依赖 `torch/torchaudio`。

**当前离线测试后端**：`cpu_reference`。数据集中每条增强样本包含 noisy 音频和 `clean_audio` 字段，用于验证增强任务的数据组织和评估产物。

**训练逻辑**：

1. 读取 `task_type=noise_enhancement` 的 50 条样本。
2. 校验 noisy/clean 音频路径和噪声类型字段。
3. 统计 paired clean-noisy 样本数。
4. 写出训练 checkpoint 和训练指标。

**评估逻辑**：

1. 读取 noisy/clean 配对样本。
2. 当前 reference 后端输出代理增强指标，用于平台流程验收。
3. 生产后端替换为 DeepFilterNet/RNNoise 后，可输出真实增强音频和真实语音质量指标。

**输出指标**：`snr_improvement`、`pesq_proxy`、`stoi_proxy`。

### 13.3 跨信道连续语音识别：`cross_channel_asr`

**模型定位**：面向多麦克风、不同采集通道或跨设备音频的连续语音识别。

**推荐开源 CPU 模型**：

- sherpa-onnx int8 streaming ASR。
- Vosk small 离线 ASR。

**当前离线测试后端**：`cpu_reference`。数据集包含 50 条跨信道样本，通道字段覆盖 `mic_array_1` 到 `mic_array_6`。

**训练逻辑**：

1. 读取 `task_type=cross_channel_asr` 样本。
2. 强制校验 `channel` 字段。
3. 统计 6 个通道的样本分布。
4. 写出训练 checkpoint，记录 `channel_count=6`。

**评估逻辑**：

1. 按 `channel` 分组。
2. 对每个通道分别计算 WER/CER。
3. 输出整体指标和 `channel_metrics`。

**输出指标**：`wer`、`cer`、`channel_metrics`。

### 13.4 小语种连续语音识别：`low_resource_asr`

**模型定位**：面向低资源语种或小语种语音数据的 ASR 垂直训练。

**推荐开源 CPU 模型**：

- Vosk small multilingual models。
- sherpa-onnx 多语种小模型。
- Whisper tiny multilingual。

**当前离线测试后端**：`cpu_reference`。数据集中该任务 50 条样本使用低资源语种标识，验证平台对 `language` 字段、文本标注和 ASR 指标的支持。

**训练逻辑**：

1. 读取 `task_type=low_resource_asr` 样本。
2. 校验 `language` 字段。
3. 统计语种分布和通道分布。
4. 输出训练 checkpoint。

**评估逻辑**：按 ASR 类流程计算 WER/CER，并输出通道维度指标。

**输出指标**：`wer`、`cer`、`channel_metrics`。

### 13.5 混合语种连续语音识别：`code_switch_asr`

**模型定位**：识别同一句或同一段音频中混合出现的多种语言，例如中英混说。

**推荐开源 CPU 模型**：

- Whisper tiny multilingual。
- sherpa-onnx bilingual 模型。
- Vosk small 作为离线 ASR 验证后端。

**当前离线测试后端**：`cpu_reference`。数据中 `language=zh-en`，文本包含混合语种形式。

**训练逻辑**：

1. 读取 `task_type=code_switch_asr` 样本。
2. 校验 `language` 多语种标识。
3. 统计样本和通道分布。
4. 写出训练结果。

**评估逻辑**：按 ASR 类流程计算 WER/CER。生产后端可增加语种切换准确率。

**输出指标**：`wer`、`cer`、`channel_metrics`。

### 13.6 声纹识别：`speaker_verification`

**模型定位**：判断两段语音是否来自同一说话人，或提取说话人 embedding 用于注册和验证。

**推荐开源 CPU 模型**：

- SpeechBrain ECAPA-TDNN：`speechbrain/spkrec-ecapa-voxceleb`。

**当前离线测试后端**：`cpu_reference`。数据包含 `speaker_id`、`enroll_speaker_id`、`test_speaker_id`、`same_speaker` 字段，用于验证声纹训练和评估流程。

**训练逻辑**：

1. 读取 `task_type=speaker_verification` 的 50 条样本。
2. 校验说话人字段。
3. 统计说话人数量。
4. 写出声纹任务 checkpoint。

**评估逻辑**：

1. 读取 `same_speaker` 标注。
2. 当前 reference 后端输出代理 EER 和验证准确率。
3. 替换为 ECAPA 后，可计算 embedding 相似度、EER、FAR、FRR。

**输出指标**：`eer_proxy`、`verification_accuracy`。

### 13.7 语音智能交互：`speech_interaction`

**模型定位**：将语音识别结果进一步映射为意图和槽位，支持语音命令、任务查询和交互控制。

**推荐开源 CPU 模型**：

- Vosk/Whisper/sherpa-onnx 作为 ASR 前端。
- MiniLM 或 DistilBERT 作为意图分类/槽位抽取文本模型。

**当前离线测试后端**：`cpu_reference`。样本包含 `intent`、`predicted_intent` 和 `slots` 字段。

**训练逻辑**：

1. 读取 `task_type=speech_interaction` 的 50 条样本。
2. 校验意图和槽位字段。
3. 统计意图类别数量。
4. 写出训练结果。

**评估逻辑**：比较 `intent` 与 `predicted_intent`，输出意图准确率和槽位 F1 代理指标。

**输出指标**：`intent_accuracy`、`slot_f1`。

### 13.8 多语言语音翻译：`speech_translation`

**模型定位**：将源语音转换为目标语种文本，通常由 ASR 前端和文本翻译模型组成，也可替换为端到端语音翻译模型。

**推荐开源 CPU 模型**：

- Whisper tiny/base multilingual，用于语音识别或 speech translation。
- Helsinki-NLP OPUS-MT tiny/小型翻译模型，用于文本翻译。

**当前离线测试后端**：`cpu_reference`。数据包含 `target_language`、`target_text`、`predicted_translation` 字段。

**训练逻辑**：

1. 读取 `task_type=speech_translation` 的 50 条样本。
2. 校验源文本、目标语种和目标文本。
3. 统计翻译样本数。
4. 写出训练结果。

**评估逻辑**：比较 `target_text` 与 `predicted_translation`，输出 BLEU/chrF 代理指标。

**输出指标**：`bleu_proxy`、`chrf_proxy`。

### 13.9 语音转写：`transcription`

**模型定位**：对长音频或会议语音进行文本转写，可扩展时间戳、标点恢复和段落切分。

**推荐开源 CPU 模型**：

- Vosk small。
- sherpa-onnx streaming ASR。
- Whisper tiny/base。

**当前离线测试后端**：`cpu_reference`。该任务与 ASR 共用识别评估逻辑，但作为独立 `task_type` 输出转写任务报告。

**训练逻辑**：读取 `task_type=transcription` 的 50 条样本，统计样本、通道和语种信息，写出 checkpoint。

**评估逻辑**：计算转写文本的 WER/CER，并按通道输出指标。

**输出指标**：`wer`、`cer`、`channel_metrics`。

### 13.10 语音纠错：`speech_correction`

**模型定位**：对 ASR 输出文本进行后处理，修正错别字、同音误识别、领域词和热词。

**推荐开源 CPU 模型**：

- pycorrector + KenLM/混淆集/领域词典。
- 小型 MacBERT/ELECTRA 纠错模型，CPU 可运行但需额外权重。

**当前离线测试后端**：`cpu_reference`。数据包含 `noisy_text`、`corrected_text`、`predicted_correction` 字段。

**训练逻辑**：

1. 读取 `task_type=speech_correction` 的 50 条样本。
2. 校验 noisy/corrected 文本对。
3. 统计纠错样本数。
4. 写出训练结果。

**评估逻辑**：比较 `corrected_text` 与 `predicted_correction`，输出 precision/recall/F1 代理指标。

**输出指标**：`correction_precision`、`correction_recall`、`correction_f1`。

## 14. 模型替换建议

当前 `cpu_reference` 后端用于平台离线验收，核心价值是稳定、快速、无需联网。生产环境替换真实开源模型时，建议保持输入输出文件格式不变，只替换 `src/speech_tasks.py` 中对应任务的训练和评估实现，确保仍输出同名指标文件：

```text
train/checkpoint.json
train/train_metrics.json
evaluate/metrics.json
summary.json
```

推荐替换顺序：

1. ASR/转写/跨信道：优先替换为 Vosk 或 sherpa-onnx。
2. 语音增强：替换为 DeepFilterNet 或 RNNoise。
3. 声纹识别：替换为 SpeechBrain ECAPA。
4. 翻译：替换为 Whisper tiny + OPUS-MT。
5. 智能交互：替换为 ASR + MiniLM/DistilBERT。
6. 纠错：替换为 pycorrector/KenLM/领域词典。
